an autonomous agent loop · built in one weekend

A model that trains, tests itself, works out what's wrong, and fixes it.

AgentForge closes the slowest loop in applied machine learning — the human staring at metrics, guessing whether to get more data, change the model, or reshape the features. The agent makes that call, one move per round, and every call is observable.

How the loop works

The task is deliberately small so the loop is the star: predict heart disease from 13 patient measurements, using public, anonymised data from four hospitals. A fixed 20% of every hospital is held out as the exam and never trained on. The agent starts with only the smallest, most skewed hospital (Switzerland, 123 patients, 93% positive) — where a model scores 55% by guessing "everyone is sick" — and must earn its way to 85%.

1 · Train
Fit a model on the data it hasAny of five model families plus a feature pipeline, chosen by earlier moves.
2 · Score
Same held-out exam every roundAccuracy, per-class recall, train/test gap and a learning-curve point — the evidence.
3 · Diagnose
Read its own history, explain whyA reasoning model (W&B Inference) reads the score and the agent's own Weave traces, cites them, and tags the problem.
4 · Decide
Pick exactly one moveTypeSafe's Jev picks one typed action with a probability on every option: get data, change model, reshape features, tune settings, or ask for a code fix.

The move is applied, and the next round's score is the measured effect of that move — recorded in an effect ledger the agent can read. It stops when it beats the target, when three moves in a row do nothing, or when it runs out of rounds. Nothing is cherry-picked: same seed, same exam, every round.

The memory test: does it learn from its own mistakes?

To make "memory" more than a slogan, one run secretly flips 40% of the labels in the VA hospital's training rows (test rows untouched, documented in the config and every log — the agent is simply not told). The question is whether it notices from its own results.

That run plateaued at 82.7% and stopped honestly instead of pretending. Without the poison, the same loop beats 85% in four to eight rounds. Both outcomes are in the console's run list.

Sponsors — what each one actually does in the loop

Track: Best Use of Weave. Each tool has a job the loop cannot do without; each one's status below is what really ran during the hackathon.

Weavethe agent's memory and the judges' evidencelive
  • Every function that trains, scores, diagnoses, decides or acts is a @weave.op; one round is one navigable trace tree.
  • Before diagnosing, the agent queries its own past evaluate/act calls through the Weave client (history.py) and the prompt asks the reasoning model to list the trace IDs it relied on — they appear in the trace and the lab report (cited_trace_ids), e.g. 01a09bc9-28d7-….
  • The three-way decision-maker comparison is a weave.Evaluation (see results).
W&B Inferencethe reasoning brainlive
  • Diagnosis runs on openai/gpt-oss-120b through the OpenAI-compatible endpoint; strict JSON out, one repair retry, honest fallback labels if it fails.
  • Also the second opinion: when the fast decision head is unsure, Inference critiques the proposal against the effect ledger and may override it with a validated action.
"The model's test accuracy (0.686) is well below the earlier peak… Adding the VA site data caused a performance drop (0.724 → 0.686)…" — a real diagnosis from the poisoned run, citing two earlier traces.
TypeSafe AIthe reflexes — one typed decision with calibrated probabilitieslive
  • System One (jev-1.13.0) does not generate text; it answers typed Choice questions with probabilities. The action head asks one request with five independent questions — which kind of move, and speculative branches for which model, which feature op, which hospital, which tuning preset — and code assembles the pydantic-validated action. Free text never reaches act().
  • Options already shown useless are withdrawn from the questions, not just discouraged: memory is binding.
  • Its confidence is a real signal: below 0.40 the loop escalates. In the poisoned run confidence fell to 0.26 the decision after the bad acquisition.
  • About 0.3 s per decision versus 7–12 s for the reasoning model at similar token counts.
marimothe lab notebook the agent writes about itselflive
  • marimo notebooks are plain Python, so notebook_writer.py appends one cell per round: the score, the effect of the last move, the diagnosis in the agent's words with cited traces, the decision with its probabilities, the cost.
  • The header cell charts accuracy against the target and auto-refreshes; a cockpit cell lets a human steer the running loop (target, blocked hospitals) and the loop records that it was steered.
ARIAthe code-fixing armprotocol built · no live fix yet
  • When every typed move is exhausted, the agent emits request_code_fix: a structured request (aria_requests/NNN.md) with the diagnosis, the failing trace IDs, and an acceptance test, asking for a new model family or feature op to be registered in extensions.py.
  • When NNN.applied lands, the loop reloads the module, re-runs the acceptance test, records who applied it (ARIA or manual-assisted) — and the new option appears in the agent's action space next round. The agent expands its own action space; the trace says who expanded it.
  • Honest status: the file protocol is implemented and tested; a live ARIA-executed fix has not been run yet.

Which decision-maker decides better? A Weave evaluation

The same 9 recorded diagnoses were replayed through three decision heads. For each proposed move we re-applied it to the recorded state, retrained on the same fixed split and measured the real change in held-out accuracy.

Honest read: with nine samples the accuracy differences are noise, and a rule baseline is competitive on a toy dataset. What is not noise: the structured head is ~20× faster than the reasoning model at the same token cost and gives a probability on every option, which the loop uses as a gate. Rules we never break

Everything observableEvery training, scoring, diagnosing and acting function is traced. Tracing is never removed to "clean up".
Honest logs onlyA sponsor tool appears in a log only if its call succeeded. Fallbacks are labeled with their cause, in the trace, the terminal and the report.
Actions are typedThe agent can only act through pydantic action models. Free text never reaches the executor.
Fixed examA stratified test split from every hospital is held out before round 0. Getting more data only grows the training pool.
Always runnablepython -m agentforge.loop --dry-run runs the whole loop offline with a rule-based brain, and must pass before every commit (71 tests).
