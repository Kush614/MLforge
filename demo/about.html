an autonomous agent loop · built in one weekend

A model that trains, tests itself, works out what's wrong, and fixes it.

AgentForge closes the slowest loop in applied machine learning — the human staring at metrics, guessing whether to get more data, change the model, or reshape the features. The agent makes that call, one move per round, and every call is observable.

UCI Heart Disease · 4 hospitalsstarts at 55%target 85%5 sponsor tools, all load-bearing

In simple words

Imagine a student taking the same exam over and over. Between attempts they have to decide how to study better — read more material, change their method, or fix a bad habit. Usually a teacher decides that. Here, the student decides for themselves, and keeps a diary of why.

The "student" is a program trying to predict heart disease from patient measurements.

The exam never changes.We set aside 185 patients as the test. The program never sees their answers, so every score is fair and comparable.
It starts badly on purpose.It only gets one small hospital where almost everyone is sick, so its first model just guesses "everyone's sick" and scores 55%. The goal is 85%.

Each round it does four things:

1
TrainBuild a model with whatever data and method it has right now.
2
ScoreTake the exam.
3
DiagnoseAn AI reads the score and its own notes from earlier rounds and writes a short explanation: "you're memorising", "you need more data", "you're stuck".
4
DecideA second, much faster AI picks exactly one move from a fixed menu — unlock another hospital's data, change the model type, reshape the inputs, tune a setting, or ask an engineer for a code change — and says how sure it is.

Then it applies the move and goes again, until it beats 85% or admits it is stuck.

Three things that make it more than a gimmick

It has a real memory.Every round is recorded in Weave. Before diagnosing, it reads its own past rounds and quotes them. Moves it already tried that didn't help are removed from its menu.
It knows when it doesn't know.If the fast AI is less than 40% sure, the program asks the slower "thinking" AI for a second opinion, which can overrule it. In our best run that overrule produced the biggest jump of the whole run.
It's honest.We secretly corrupted one hospital's data. The program noticed its score fell after adding it, wrote that down, grew less confident, and eventually stopped rather than pretend. If any tool fails, the log says so.

Result: on its own, it went from 55% to 87% in six rounds — better than the published score for this dataset, and almost as good as a human expert hand-tuning the model.

What you see on screen is a diagram of that loop with a dot moving between the steps, hospitals lighting up as they are unlocked, a gauge climbing toward the target, and one plain-English sentence per step, like "It scored 69.2% — that's 0.5 points worse than last round. It's only 21% sure what to do next, so it's asking for a second opinion."

The real point isn't that the number went up. It's that you can click any round and see exactly why it went up — and the same machinery tells you when it's stuck.

How the loop works

The task is deliberately small so the loop is the star: predict heart disease from 13 patient measurements, using public, anonymised data from four hospitals. A fixed 20% of every hospital is held out as the exam and never trained on. The agent starts with only the smallest, most skewed hospital (Switzerland, 123 patients, 93% positive) — where a model scores 55% by guessing "everyone is sick" — and must earn its way to 85%.

1 · Train
Fit a model on the data it hasAny of five model families plus a feature pipeline, chosen by earlier moves.
2 · Score
Same held-out exam every roundAccuracy, per-class recall, train/test gap and a learning-curve point — the evidence.
3 · Diagnose
Read its own history, explain whyA reasoning model (W&B Inference) reads the score and the agent's own Weave traces, cites them, and tags the problem.
4 · Decide
Pick exactly one moveTypeSafe's Jev picks one typed action with a probability on every option: get data, change model, reshape features, tune settings, or ask for a code fix.

The move is applied, and the next round's score is the measured effect of that move — recorded in an effect ledger the agent can read. It stops when it beats the target, when three moves in a row do nothing, or when it runs out of rounds. Nothing is cherry-picked: same seed, same exam, every round.

The memory test: does it learn from its own mistakes?

To make "memory" more than a slogan, one run secretly flips 40% of the labels in the VA hospital's training rows (test rows untouched, documented in the config and every log — the agent is simply not told). The question is whether it notices from its own results.

That run peaked at 82.7% and stopped honestly instead of pretending. Without the poison, the same loop beats 85% in four to eight rounds — the full round-by-round tables for both are in the results below.

Sponsors — what each one actually does in the loop

Track: Best Use of Weave. Each tool has a job the loop cannot do without; each one's status below is what really ran during the hackathon.

Weavethe agent's memory and the judges' evidencelive
  • Every function that trains, scores, diagnoses, decides or acts is a @weave.op; one round is one navigable trace tree.
  • Before diagnosing, the agent queries its own past evaluate/act calls through the Weave client (history.py) and the prompt asks the reasoning model to list the trace IDs it relied on — they appear in the trace and the lab report (cited_trace_ids), e.g. 01a09bc9-28d7-….
  • The three-way decision-maker comparison is a weave.Evaluation (see results).
W&B Inferencethe reasoning brainlive
  • Diagnosis runs on openai/gpt-oss-120b through the OpenAI-compatible endpoint; strict JSON out, one repair retry, honest fallback labels if it fails.
  • Also the second opinion: when the fast decision head is unsure, Inference critiques the proposal against the effect ledger and may override it with a validated action.
"The model's test accuracy (0.686) is well below the earlier peak… Adding the VA site data caused a performance drop (0.724 → 0.686)…" — a real diagnosis from the poisoned run, citing two earlier traces.
TypeSafe AIthe reflexes — one typed decision with calibrated probabilitieslive
  • System One (jev-1.13.0) does not generate text; it answers typed Choice questions with probabilities. The action head asks one request with five independent questions — which kind of move, and speculative branches for which model, which feature op, which hospital, which tuning preset — and code assembles the pydantic-validated action. Free text never reaches act().
  • Options already shown useless are withdrawn from the questions, not just discouraged: memory is binding.
  • Its confidence is a real signal: below 0.40 the loop escalates. In the poisoned run confidence fell to 0.26 the decision after the bad acquisition.
  • About 0.3 s per decision versus 7–12 s for the reasoning model at similar token counts.
marimothe lab notebook the agent writes about itselflive
  • marimo notebooks are plain Python, so notebook_writer.py appends one cell per round: the score, the effect of the last move, the diagnosis in the agent's words with cited traces, the decision with its probabilities, the cost.
  • The header cell charts accuracy against the target and auto-refreshes; a cockpit cell lets a human steer the running loop (target, blocked hospitals) and the loop records that it was steered.
ARIAthe code-fixing armprotocol built · no live fix yet
  • When every typed move is exhausted, the agent emits request_code_fix: a structured request (aria_requests/NNN.md) with the diagnosis, the failing trace IDs, and an acceptance test, asking for a new model family or feature op to be registered in extensions.py.
  • When NNN.applied lands, the loop reloads the module, re-runs the acceptance test, records who applied it (ARIA or manual-assisted) — and the new option appears in the agent's action space next round. The agent expands its own action space; the trace says who expanded it.
  • Honest status: the file protocol is implemented and tested; a live ARIA-executed fix has not been run yet.

Results, in detail

The setup every number below shares

920 patients from four hospitals. Before round 0, a stratified 20% of every hospital is set aside as the exam: 185 patients, 55% of them with disease. The exam never changes and is never trained on, so "guess everyone is sick" scores exactly 55.1% — that is the floor the agent starts on, with only Switzerland's 98 training rows (93% positive). The target is 85%; the best published single-hospital accuracy on this dataset is 78.7–83.3%.

For context, here is what a human-picked configuration scores on the same exam when handed all four hospitals at once (no agent involved):

Hand-picked configuration, all 4 hospitalsAccuracy
k-nearest neighbours, raw features70.3%
k-nearest neighbours, standardised83.2%
logistic regression, standardised85.4%
random forest, defaults85.9%
random forest, tuned by hand (300 trees, depth 8)88.1%

So the question the runs answer is not "can a model reach 85%" — it is whether an agent starting blind, with one bad hospital and a bad model, can find its way there on its own evidence, and whether every step of that is legible.

What happened in round 3, exactly. Two moves in a row had made things slightly worse. Jev's top choice was "get more data" at only 38%. The second opinion read the diagnosis and the effect ledger and wrote:

"The diagnosis identifies data scarcity and class imbalance as the primary issues. Acquiring additional Hungarian data has already been attempted repeatedly with minimal or negative impact… Switching to a model that is less prone to overfitting on small, imbalanced datasets — such as logistic regression with regularization — offers a more promising path."

The override was right on outcome: +15.7 points the next round, the largest single gain of the run. It was also partly wrong on facts — Hungary had not been acquired in this run. The agent's memory is the whole Weave project, so it was reading traces from earlier runs where Hungary had been tried. That is the honest shape of "memory is its own trace history": it works across runs, and it can conflate them. It is called out again under limitations.

Cost of the run. Five structured decisions by TypeSafe: mean 0.26 s, ~2,570 input / 210 output tokens each. Five diagnoses and one second opinion by W&B Inference: 7–12 s each. Every diagnosis cited between 2 and 5 earlier trace IDs. No dollar figures are reported because no price sheet was available; the loop reports "n/a" rather than a guess.

What the agent got right. Its own ledger recorded VA as the only acquisition that ever hurt (−3.8 pts), and the diagnosis in round 2 said so in words: "Adding the VA site data caused a performance drop (0.724 → 0.686, see trace 01a09bc9-28d7…)". Its confidence dropped from 85% to 53% on the very next decision. Settings it had already tried were withdrawn from its options, so the tuning sequence in rounds 3–5 never repeated itself. When it ran out of good ideas it stopped rather than pretend.

What it got wrong. It never unlocked Hungary — the one clean hospital left — and instead spent six rounds tuning and switching models around the noisy data. Model families are only marked as tried, not withdrawn (revisiting one can be legitimate after the data changes), so it went back to random forest twice. A stronger agent would have treated "the last acquisition hurt" as a reason to try the other acquisition, not to stop acquiring.

Run-to-run variation and limitations

  • Variance. The diagnosis runs at temperature 0.2 and Jev's choices are probabilistic, so clean runs beat the target in 4 to 8 rounds by different routes (an Inference-decided run reached 85.4% in 4; a TypeSafe-decided run 85.9% in 8; the run above 87.0% in 6). Some poisoned runs also beat the target when a strong model masks the noise.
  • Cross-run memory. The agent reads the whole Weave project, so it remembers earlier runs — useful (it knows logistic regression peaked at 0.849 before) and confounding (round 3's critique cited a Hungary attempt from another run). Scoping history to the current run is a one-line change; leaving it project-wide was a deliberate choice for the demo, and it is disclosed here.
  • Small n everywhere. Nine decisions per run, one exam of 185 patients. A ±2-point swing is inside the noise of that exam.
  • The dataset is a toy. The contribution is the loop — typed actions, binding memory, calibrated uncertainty gating a second opinion, and total observability — not the heart-disease number.

Findings, briefly

1 · It gets there on its own evidence.Starting blind at 55.1% with one skewed hospital and the wrong model, the agent reached 87.0% in six rounds — above the 85% target, above the 78.7–83.3% published range, and within a point of the best hand-picked configuration (88.1%).
2 · Data first, model second — learned, not told.In every clean run the first two moves were acquisitions, and the largest single gains came from unlocking a hospital (+17.3, +15.7 pts). Nobody encoded "get data before tuning"; it read it off its own ledger.
3 · Calibrated uncertainty is useful control signal.The structured head's confidence fell to 21% exactly when two moves in a row had failed. Gating on that and asking for a second opinion produced the run's best move (+15.7 pts). Confidence tracked trouble in the poisoned run too (85% → 53%).
4 · Memory works — and needs scoping.Diagnoses cited 2–5 earlier Weave traces each; in the poisoned run the agent named the harmful acquisition and its trace ID in words. But memory spans the whole project, so one critique mixed in a fact from a previous run. Feature and confound in the same mechanism.
5 · Binding memory beats advisory memory.Withdrawing already-tried settings from the options ended a +0.114/−0.114 preset oscillation. Families are still only marked, and the agent duly re-tried one twice — the gap between the two behaviours is visible in the tables.
6 · The fast head is not the smart head, and doesn't need to be.On nine replayed decisions, rules (+0.054), TypeSafe (+0.046) and the reasoning model (+0.038) are within noise of each other on outcome; TypeSafe is ~20× faster at equal tokens and gives probabilities. The right architecture is fast structured reflexes with a slow reasoner on call — which is what the gate is.

Summary

AgentForge is a closed train → score → diagnose → decide loop whose every step is a typed, traced, measurable event. Two LLMs share the work by strength: a reasoning model explains and, when asked, arbitrates; a structured-decision model picks one move in a third of a second with a probability on each option. The agent's memory is its own trace history, and the memory is binding — options shown useless disappear. On a deliberately small problem it goes from a majority-class guess to 87% without a human, and when we poison a data source it notices from its own results, hedges, and stops rather than pretend. What is stubbed is stated: the ARIA code-fix path is built but has not executed a live fix, and history is project-wide by choice.

If you take one thing away: the interesting part is not that the number went up. It is that you can click any round and see exactly why it went up — the evidence, the diagnosis, the probabilities, the override — and that the same machinery told us when it was stuck.

Rules we never break

Everything observableEvery training, scoring, diagnosing and acting function is traced. Tracing is never removed to "clean up".
Honest logs onlyA sponsor tool appears in a log only if its call succeeded. Fallbacks are labeled with their cause, in the trace, the terminal and the report.
Actions are typedThe agent can only act through pydantic action models. Free text never reaches the executor.
Fixed examA stratified test split from every hospital is held out before round 0. Getting more data only grows the training pool.
Always runnablepython -m agentforge.loop --dry-run runs the whole loop offline with a rule-based brain, and must pass before every commit (71 tests).
